 要件定義（確定版）

 1. 目的

 LLM を内蔵したモジュールが「自分の役割に合わせて自分自身を書き換え・進化」し、複数モジュールが「対話・交渉」して機能を完成させるアーキテク
 チャを、Elixir/BEAM 上で実際に動くサンプルとして作る。同じ機構で目的の異なるアプリを量産できることを確認する。

 2. 機能要件

 FR-1. エージェント定義はデータとして外出し

   • 役割・プロンプト・コード雛形・ツール一覧・評価対象を EDN/ファイルとして保持
   • 実行系は定義を読み込んでインスタンス化。定義変更で実行系は再起動しない

 FR-2. 自己書き換えループ

   • LLM に改善案を生成させ、新バージョンを  Code.compile_string  →  :code.load_binary  で実行中にロード
   • バージョンは  Agent.V001 ,  V002 … と別モジュール名で保持し、ポインタで現行版を切替（ロールバック可）
   • バージョン・スコア・親・日時を  evolution/<app>.jsonl  に記録

 FR-3. 評価器

   •  evaluate/2  をアプリごとに定義。タスク集合を流してスコア化
   • 評価はタイムアウト付き別プロセスで実行し、暴走を隔離
   • 採用判定: 新スコア > 現行なら archive 追加＋現行更新、 otherwise 破棄

 FR-4. エージェント間協調（1対1 / 1対多 / 多対多）

   • 輸送層:  Envelope {from, to|topic, type, payload}  の構造化データ。 to  は特定プロセス / 役割名 / トピックを指定可
   • 認知層: 各プロセス内の LLM が payload（自然言語）を解釈し返答を生成。LLM 呼び出しは輸送に含めない
   • プリミティブ:  broadcast(proposal)  /  collect(proposal_id, timeout) （ファンイン）/  claim(task) （Contract Net 型）
   • 合意判定はアプリ側が定義（全員一致 or スコア）
   • ETS 共有 blackboard をオプションで利用可

 FR-5. LLM アクセス

   •  req_llm  経由で API を呼ぶ。キーは環境変数（ .env ）、コード・git に含めない

 FR-6. アプリ量産の抽象化

   •  use AgentLab.App  で  evaluate/2 ・ tasks/0 ・ agents/0  を実装すれば共通機構が動く
   • 第1弾  function_optimizer （単体）、第2弾  travel_planner （複数）

 FR-7. 動的プロセス生成・委譲

   • エージェントはツールとして  spawn_agent  /  delegate  /  list_processes  を持つ
   • spawn されたプロセスは  DynamicSupervisor  管理・ Registry  登録
   • 一時タスクは  Task.Supervisor （タイムアウト・自動終了）、長期エージェントは  GenServer
   • 生成コードの実行・評価は必ず別プロセスで行い親を落とさない
   • spawn されたプロセスも同じ Definition/Version/Archive 機構を継承し、再帰的に spawn 可能

 3. 非機能要件

   • 再起動なし: 自己書き換え・プロセス生成のいずれでも VM/アプリ再起動を要求しない
   • 監査可能性: バージョン・スコア・メッセージをすべてログに残す
   • 安全性: LLM 生成コードは別プロセス＋タイムアウトで隔離（Docker 等の本格隔離はスコープ外）
   • 言語: Elixir/OTP。依存は最小限（req_llm, jason 程度）

 4. スコープ外

   • 複数ノード分散、A2A/MCP 準拠、外部公開 Web サービス、重み更新（fine-tuning）、Docker 等による OS レベル完全隔離

 5.1 Phase 5 追加機能要件（詳細設計は docs/architecture.md 参照）

   FR-8. 落ちない核と動的アプリ空間の分離
   • チャット窓口・AI エージェント（Core）と生成アプリ（App Space）を Supervision Tree で分離
   • 生成モジュールは Smap.UserApp.* 名前空間のみ許可し、危険呼び出し（System.halt 等）を AST 検査で拒否
   • コンパイル・描画・リクエスト処理はタイムアウト付き別プロセス実行＋失敗時自動ロールバック

   FR-9. ローカル Web UI と常駐チャット窓口（Windows 日本語 GUI 対応）
   • Bandit + Plug + SSE によるローカル HTTP サーバー（127.0.0.1、既定ポート 0 自動割当）
   • Windows で Edge アプリモード（または既定ブラウザ）を自動起動し、日本語 IME 入出力・音声/メディア再生に対応
   • 常設チャットパネル＋差し替え可能なアプリ表示スロット構成、ホットスワップ時に SSE で無停止画面更新

   FR-10. 内包 AI エージェントの継続的自己改修ループ（Tool Use）
   • 会話履歴・現行ソース・稼働状態・直近エラーを保持し、ツール実行で段階的にアプリを拡張・自己修正

   FR-11. 成長状態の永続化と複数インスタンス共存
   • 実行ファイル単位の独立データディレクトリ（<exe_basename>.smap-data/ 等）へソース・履歴・アプリデータを保存
   • 再起動時に現行安定バージョンを自動復元（破損時は前バージョンまたは初期チャットへ安全フォールバック）
   • エフェメラルポート自動割当＋Elixir 側 Storage 規約により同一 PC 上で複数インスタンス同時稼働可能

   FR-12. 単一バイナリ配布
   • Burrito / mix release により mix やソースツリー不要の単一バイナリとして配布・実行可能
